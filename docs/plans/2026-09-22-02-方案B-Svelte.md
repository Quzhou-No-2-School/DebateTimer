## 3. 关键实现要点

### 3.1 高频 tick：Svelte 的细粒度响应式天然适配

Svelte 5 编译期就知道哪个文本节点依赖哪个变量，更新只改那一个节点，**没有 VDOM diff**。所以可以直接把剩余时间放进 `$state`，不需要 A 方案那种"绕过框架直写 DOM"的绕路。

```ts
// lib/timer.svelte.ts
import { TimerEngine } from "../core/engine";

export const engine = new TimerEngine();

class TimerView {
  remainMs = $state(0);
  status = $state<"idle" | "running" | "paused" | "finished">("idle");
  stageIndex = $state(0);

  constructor() {
    engine.onTick((s) => {
      this.remainMs = s.remainMs;
      this.status = s.status;
    });
  }
}
export const timer = new TimerView();
```

```svelte
<!-- TimerDisplay.svelte -->
<div class="font-semibold tabular-nums" style="font-size: clamp(4rem, 22vh, 24rem)">
  {format(timer.remainMs)}
</div>
```

### 3.2 动画几乎免费

```svelte
<!-- PromptOverlay.svelte：提示横幅 -->
{#if prompt}
  <div
    in:fly={{ y: -24, duration: 260, easing: cubicOut }}
    out:fade={{ duration: 180 }}
    class="..."
  >
    {prompt.label}
  </div>
{/if}
```

环节切换、数字颜色过渡（正常 → 30s 琥珀 → 到点红）、控制条淡出，全部用内置 transition/`tweened` 完成，不需要装 `motion`。

### 3.3 engine / 提示点 / 时钟校准

与总览 §3.3 完全一致（`core/` 三方案共用，零框架依赖）：

- 提示点预算成绝对时间戳数组，tick 做"跨过检测"，休眠醒来一次性补触发；
- `performance.now()` 为主、`Date.now()` 为裁判，偏差 > 1s 判定休眠并按墙钟重算 deadline。

### 3.4 Tauri 侧

与 A 一致：单窗口全屏配置、按需 capabilities、不引入全局热键（窗口内 `keydown` 足够）。
Svelte 需确保构建产物是**纯静态 SPA**（`ssr = false`，禁用 prerender），否则 Tauri 加载会失败：

```js
// svelte.config.js
export default { compilerOptions: {}, kit: { adapter: adapterStatic? } }
```

> 注：若用 **SvelteKit**，必须配 `adapter-static` + `ssr: false`；若直接用 **Vite + Svelte（非 Kit）**，则天然是 SPA，配置更少——**本项目单屏、无路由，推荐直接用 `vite` + `svelte` 插件，不引入 SvelteKit**。

### 3.5 字体与离线

字体 woff2 放 `src/assets/fonts/`，CSS `@font-face` 本地引用，**不引 Google Fonts CDN**（教室可能没网）。

## 6. B 方案特有风险

| 风险                                                          | 对策                                                               |
| ------------------------------------------------------------- | ------------------------------------------------------------------ |
| Svelte 5 runes 心智模型与 React 不同（`$state` 是编译期魔法） | `core/` 保持纯 TS 不碰 runes，只有 `lib/*.svelte.ts` 薄封装用      |
| 生态小于 React，第三方组件少                                  | 本项目组件自制，无对外依赖需求                                     |
| SvelteKit vs 纯 Vite+Svelte 选错会增加配置                    | **选纯 `vite` + `svelte` 插件**，无路由需求，避免 SSR/prerender 坑 |
| 未来若要招人接手，会 Svelte 的人少于 React                    | 若这是长期多人项目，改选方案 A                                     |

---

## 7. 选 B 的理由 / 不选 B 的理由

**选（推荐）**：本项目规模小但要求"UI 精美 + 动效顺滑"，Svelte 内置动画 + 细粒度更新是最短路径；产物最小（~10-15KB 运行时），老旧多媒体电脑启动最快；代码量比 A 少约 30-40%。
**不选**：你需要 React 生态，或这是长期多人协作项目。
