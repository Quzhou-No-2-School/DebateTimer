# DebateTimer 实施计划（方案 B：Svelte 5 + V1 瑞士白 + Web Audio）

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 做一个跨平台的辩论赛计时器桌面程序：单屏全屏、浅色简洁（V1 瑞士白），内置 5 套辩论赛流程并支持自定义，Web Audio 合成提示音，快捷键完整，辩题可现场修改。

**Architecture:** Tauri 2 提供桌面壳；`src/core/` 是**纯 TypeScript、零框架零 Tauri 依赖**的领域层（计时引擎、数据模型、赛制、音频、快捷键、存储），可用 Vitest 完整单测；`src/lib/` 用 Svelte 5 runes 把 core 包成响应式状态；`src/components/` 只做视图。计时以 `deadlineAt` 绝对时间戳为准（不靠 tick 累加），提示点预计算时间戳并在 tick 做"跨过检测"，休眠/掉帧后补触发不丢。

**Tech Stack:** Tauri **2.11.6** · Svelte **5.56.3**（runes）· **SvelteKit 2.65.1 + adapter-static（`ssr = false`，SPA 模式）** · TypeScript **6.0.3** · Vite **8.0.16** · Tailwind CSS **4.3.3**（`@tailwindcss/vite`）· Vitest · npm（**pnpm 本机不可用**）

> **脚手架实测校正（2026-09-22）**：`create-tauri-app` 的 `svelte-ts` 模板现已默认使用 **SvelteKit + `@sveltejs/adapter-static`（`fallback: index.html`）+ `src/routes/+layout.ts` 里 `export const ssr = false`**，即官方已经把 SPA 模式配好了。原方案里"避免 SvelteKit、改用纯 vite+svelte"的判断作废——**直接沿用官方模板**风险最低，dev/host/port 的 Tauri 适配也已现成。

**已确认约束：** 三平台同等（Windows/macOS/Linux）· 单屏全屏 · 浅色简洁 · 只做计时本身（**不做**赛后用时记录与导出）

### Task 3: 时钟 `src/core/clock.ts`（可注入，便于测试）

**Files:** Create `src/core/clock.ts`, Test `src/core/clock.test.ts`

**权威时钟以墙钟 `Date.now()` 为准**（不是 performance.now）——实测认知修正：`performance.now` 基于 CLOCK_MONOTONIC，**不计系统休眠时间**，以它为准会让电脑睡 3 分钟后计时器凭空多出 3 分钟。`performance.now` 只在墙钟**回拨**时用来顶上。

**Step 1: 写失败测试**

```ts
// 注入式时钟：perf 与 wall 可分别推进，用于模拟休眠与时钟回拨
it("休眠后墙钟照常推进、单调时钟停滞 → 仍按墙钟计", () => {
  expect(authoritativeDelta(0, 60_000)).toBe(60_000);
});
it("墙钟回拨时退回单调时钟", () => {
  expect(authoritativeDelta(1000, -5_000)).toBe(1000);
});
```

**Step 2:** 跑 `npx vitest run src/core/clock.test.ts` → 期望 FAIL（模块不存在）。

**Step 3:** 实现 `TimeSource { perf(), wall() }`、`systemTimeSource()`、`authoritativeDelta(perfDelta, wallDelta)`：墙钟正常前进（含休眠）以墙钟为准，`wallDelta < 0` 时返回 `perfDelta`。

**Step 4:** 测试通过 → 提交 `git commit -m "feat(core): injectable clock with wall-clock drift detection"`。

### Task 4: 计时引擎 `src/core/engine.ts`（核心）

**Files:** Create `src/core/engine.ts`, Test `src/core/engine.test.ts`

**Step 1: 写失败测试**（覆盖以下 8 条，全部用注入时钟，绝不用真实 `sleep`）

1. `start()` 后推进 1s → 剩余减少 1s
2. `pause()` 推进 10s 再 `resume()` → 剩余不变（不丢时、不多走）
3. 剩 30s 提示点：跨过时触发**恰好一次**，再推进不再重复触发
4. 休眠场景：一次推进跨过 30s 与 0s 两个提示点 → 两个都触发且顺序正确（补触发）
5. 到点 → `status === 'finished'`；`overtime: 'count'` 时继续累计超时秒数
6. `adjust(+10_000)` → 剩余 +10s，且未触发的提示点按新 deadline 重算
7. `alternating` 模式：正/反两块表独立，`switchSide()` 只影响当前方
8. `split` 模式（盘问）：提问桶与回答桶分别计时、分别触发各自提示

**Step 2:** `npx vitest run src/core/engine.test.ts` → FAIL。

**Step 3:** 实现 `TimerEngine`：

- 状态机 `idle | running | paused | finished`
- 持有 `deadlineAt`（绝对时间戳）、`pausedAccum`、`marks: {at, rule, fired}[]`
- `tick(now)`：算 `remainMs = deadlineAt - now`；遍历 marks 做跨过检测并 `emit`
- 休眠校准：tick 时用 `clock.checkDrift()` 修正 `deadlineAt`
- API：`start / pause / resume / reset / next / prev / goto / adjust / switchSide / loadStage / subscribe`
- `onTick(cb)` 供 UI 订阅；`on('prompt', cb)` 供音频与横幅订阅

**Step 4:** 全部通过 → 提交 `git commit -m "feat(core): timer engine with absolute-deadline prompt marks"`.

### Task 5: 提示音 `src/core/audio.ts`（Web Audio 合成）

**Files:** Create `src/core/audio.ts`

**Step 1:** 用 `AudioContext` + `OscillatorNode` + `GainNode` 合成三种音：

- `short`：单声短铃（880Hz，衰减 0.25s）
- `bell`：钟声（基频 + 泛音，衰减 1.2s）
- `double`：两声（间隔 250ms）

**Step 2:** 支持 `repeat: 1 | 2 | 3`（奥瑞冈需要一/两/三声）与音量。

**Step 3:** **首次用户交互时 resume AudioContext**（浏览器自动播放策略），否则现场第一次响铃会静音——这是真实坑，必须处理。

**Step 4:** 手动验证：`npm run tauri dev` 后按快捷键触发，确认出声与音量可调。

**Step 5:** 提交 `git commit -m "feat(core): web audio synthesized prompt tones"`.
