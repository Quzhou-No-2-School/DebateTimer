## 2. 三套方案对比

| 维度           | **A. React 19**                                                    | **B. Svelte 5（推荐）**                  | **C. 原生 TS 无框架**                   |
| -------------- | ------------------------------------------------------------------ | ---------------------------------------- | --------------------------------------- |
| 前端栈         | React 19 + TS + Vite + Tailwind 4 + Zustand                        | Svelte 5(runes) + TS + Vite + Tailwind 4 | TS + Web Components + Vite + Tailwind 4 |
| 运行时体积     | ~45KB gzip + React 运行时                                          | ~10-15KB（编译后几乎无运行时）           | ~0                                      |
| 计时器每帧更新 | 需小心：用 `useSyncExternalStore` 只让数字组件订阅，否则整树重渲染 | 细粒度响应式，天然只更新那个文本节点     | 手写订阅，直接改 `textContent`          |
| 动画           | 需 `motion` 13 或纯 CSS                                            | 内置 `transition`/`spring`/`fly`，零依赖 | 纯 CSS（足够）                          |
| 代码量         | 基准 100%                                                          | 约 60-70%                                | 约 130%（列表编辑器啰嗦）               |
| 生态/可维护性  | 最好，招人最容易                                                   | 好但小众                                 | 无框架升级负担，但全靠自己              |
| 上手门槛       | 低（资料最多）                                                     | 中（runes 需适应）                       | 低但体力活多                            |
| 适合           | 想长期扩展（双屏、复杂编辑器、插件）                               | **本项目当前规模最合适**                 | 追求极致小/极致稳定                     |

**推荐方案 B**：本项目 UI 复杂度中等（一个全屏屏 + 一个设置/编辑面板），但动效与「精美」要求高，Svelte 的内建动画 + 细粒度响应式恰好是最短路径；产物最小，老旧多媒体电脑启动最快。
**选 A 的理由**：你更看重 React 生态/未来扩展/团队协作。
**选 C 的理由**：你想十年后打开还能跑、且不想被框架版本牵着走。

## 3. 共用核心设计（三方案一致）

### 3.1 分层

```
core/     纯 TS，零框架依赖，可脱离 Tauri 用 Vitest 单测
  ├─ models.ts    类型定义（Stage / FlowTemplate / PromptRule）
  ├─ engine.ts    计时引擎（状态机 + 时钟 + 提示点触发）
  ├─ presets.ts   内置赛制
  ├─ storage.ts   持久化（localStorage → 后续 tauri-plugin-store）
  ├─ audio.ts     Web Audio 合成铃声
  └─ hotkeys.ts   快捷键映射 + 输入态屏蔽
ui/       视图层（各方案不同）
```

**核心原则：`core/` 不 import 任何 UI 框架、不 import Tauri API**，这样计时逻辑可以纯单测覆盖。

### 3.2 数据模型（`core/models.ts`）

```ts
export type Side = "pro" | "con" | "neutral";

export type TimingMode =
  /** 单边倒计时：一个表走完 */
  | { kind: "single"; limitSec: number }
  /** 双计数分计：同一环节两块表（如盘问：提问累计 1min / 回答累计 3min） */
  | { kind: "split"; buckets: { id: string; label: string; limitSec: number }[] }
  /** 双边分离计时：自由辩论，双方各一块表，一方停下即切另一方 */
  | { kind: "alternating"; perSideSec: number; firstSide: "pro" | "con" };

export interface PromptRule {
  atRemainingSec: number; // 剩余 N 秒触发
  label?: string; // 屏幕提示文字，如"还剩 30 秒"
  sound?: "short" | "bell" | "double"; // 短铃 / 钟声 / 双响
  flash?: boolean; // 是否闪烁强调
}

export interface Stage {
  id: string;
  name: string; // "正方一辩立论"
  side: Side;
  speaker?: string; // "一辩"，可现场编辑
  timing: TimingMode;
  prompts: PromptRule[]; // 多级提示点（奥瑞冈需要 60/30/0 三级）
  overtime: "stop" | "count"; // 时间到：停止 or 继续计超时
}

export interface FlowTemplate {
  id: string;
  name: string; // "新加坡模式（四人制）"
  builtin: boolean;
  stages: Stage[];
}

export interface MatchState {
  topic: string; // 辩题，可随时改
  proName: string; // 正方名称（默认"正方"）
  conName: string;
  templateId: string;
  stageIndex: number;
}
```

### 3.3 计时引擎（`core/engine.ts`）—— 本项目最需要严谨的地方

| 问题                      | 做法                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `setInterval` 累积漂移    | **不靠 tick 累加**。记录 `deadlineAt` 绝对时间戳，每次渲染用 `now` 重新算剩余时间                                                          |
| 掉帧/后台节流漏掉提示点   | 提示点预计算成**绝对时间戳数组**，tick 时判断"已跨过且未触发过"→ 补触发，绝不漏                                                            |
| 系统休眠/锁屏后时钟不一致 | 每 tick 比对 `performance.now()` 与 `Date.now()` 的推进量，偏差 > 1s 判定为休眠，**以墙钟 `Date.now()` 重算 deadline**（比赛现场必须可靠） |
| 渲染驱动                  | `requestAnimationFrame`；页面不可见时降级为 500ms `setInterval`                                                                            |
| 状态机                    | `idle → running → paused → finished`，暂停记录 `pausedAccum`，恢复时顺延 deadline                                                          |

对外接口：`start() / pause() / resume() / reset() / nextStage() / prevStage() / gotoStage(i) / adjust(±sec) / subscribe(cb)`。

### 3.4 提示系统

- **可配置多级提示点**，默认：剩 30s 一声短铃 + 屏幕上浮"还剩 30 秒"；时间到 钟声（双响）+ 数字变红 + "时间到"横幅。
- **声音用 Web Audio 实时合成**（OscillatorNode + GainNode 包络），**不打包音频文件**：省体积、可调节音色/音量/响铃次数，且不会有素材版权问题。
- 需要"一声/两声/三声"（奥瑞冈）→ `sound` + `repeat` 参数即可覆盖。
- 视觉提示同时提供**举牌式文字**（"30 秒"/"时间到"），因为现场不一定开声音。

### 3.5 快捷键（默认映射，可在设置里改）

| 键                 | 动作                                  |
| ------------------ | ------------------------------------- |
| `Space`            | 开始 / 暂停当前环节                   |
| `Enter` 或 `→`     | 下一环节                              |
| `Backspace` 或 `←` | 上一环节                              |
| `R`                | 重置当前环节                          |
| `Tab`              | 自由辩论：切换发言方（双边计时）      |
| `+` / `-`          | 当前环节 ±10 秒（`Shift+` 为 ±60 秒） |
| `1`–`9`            | 直接跳到第 N 个环节                   |
| `T`                | 编辑辩题（内联，不打断计时）          |
| `F11` / `F`        | 全屏切换                              |
| `H`                | 快捷键帮助面板                        |
| `Esc`              | 关闭弹窗 / 退出编辑                   |

**硬要求**：单键快捷键在 `<input>`/`<textarea>` 聚焦（改辩题、改时长）时必须屏蔽，否则打字会误触发计时。
**待实测**：`F11` 在部分 WebView 下被系统层拦截，若不可用则退化为 `F` 键 + 界面按钮（Tauri 的 `window.setFullscreen()` 不受影响）。

### 3.6 持久化

- 起步：纯 `localStorage`（自定义赛制、辩题、偏好设置）。
- 进阶（M4）：`tauri-plugin-store` 或手写 JSON 到应用数据目录，支持**赛制模板导入/导出 JSON**（拷给别的老师用）。
- 内置赛制只存 `builtin: true` 的引用，不随用户改动被污染；用户改内置模板时自动"另存为自定义"。

## 4. 内置赛制清单（调研所得，均附来源）

| 模板                     | 环节与时长                                                                                                                                                              | 提示规则                                                                               | 来源                                                                                 |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **新加坡模式（四人制）** | 正一陈词 3-4 / 反一 3 / 正二 3 / 反二 3 / 正三 3 / 反三 3 → 自由辩论双方各 4-5 → 反四总结 4 / 正四总结 4。无攻辩环节                                                    | 通用 30s 提示                                                                          | https://wikis.pro/新加坡制                                                           |
| **四辩制（大学常见）**   | 立论 3/3 → 立证陈词 3/3 → 盘问（提问累计 1min、回答累计 3min）→ 自由辩论双方各 5（总 10）→ 反四总结 4 / 正四总结 4                                                      | 剩 30s 举牌，用时满终止                                                                | https://qgdxygqt.qit.edu.cn/info/1044/3602.htm                                       |
| **四辩制（山东科大版）** | 立论 3 → 驳立论 2 → 质辩盘问 1分30（单边计时，被盘问方不计）→ 自由辩论双方各 4 → 总结各 3                                                                               | —                                                                                      | https://yjsy.sdust.edu.cn/.../69D47B3D_5E00.doc（.doc 抓取失败，仅摘要，时长待复核） |
| **三人制（中学）**       | 立论 3（2:30 黄牌/3:00 红牌）→ 驳论 1 → 攻辩四轮（攻方 1min/45s 黄牌，辩方 1:30/1:15 黄牌）→ 攻辩小结 1:30 → 自由辩双方各 5（4:30 黄牌，反方先）→ 总结各 3（2:30 黄牌） | 黄牌/红牌两级                                                                          | https://doc.guandang.net/b35556c055b064e9d6bc026e5ca55b064e9d6.html                  |
| **奥瑞冈「五四四」**     | 7 轮：申论 5 → 质询 4 交替（6 轮）→ 双方结辩各 4                                                                                                                        | 申论：4:00 一声 / 4:30 两声 / 5:00 三声；质询与结辩：3:00 一声 / 3:30 两声 / 4:00 三声 | https://zhuanlan.zhihu.com/p/645628336                                               |
| **空白自定义**           | 从零添加环节                                                                                                                                                            | 默认 30s + 到点                                                                        | —                                                                                    |

**重要调研结论**：

1. **没有任何全国统一强制标准**，30 秒提示只是行业惯例 → 所有数字必须可改。
2. 自由辩论绝大多数是**双方分别计时**（不是共用一块表），一方落座即启动另一方计时 → 引擎必须有 `alternating` 模式。
3. 部分环节是**单边计时**（盘问只计提问方）或**双计数分计**（提问/回答各一块表）→ 引擎必须有 `split` 模式。
4. 奥瑞冈在中文语境下有"三人五四四"和"四人制"两个版本 → 分开做两个模板。

## 5. 视觉方向（浅色简洁下的三个子方向，可再挑）

设计系统生成结果（ui-ux-pro-max，`--variance 3 --motion 4 --density 3`）推荐：**Minimalism & Swiss Style**，字体 Plus Jakarta Sans。

| 方向                  | 底色      | 文字      | 强调色         | 阵营色                    | 气质                                           |
| --------------------- | --------- | --------- | -------------- | ------------------------- | ---------------------------------------------- |
| **V1 瑞士白（推荐）** | `#FFFFFF` | `#0F172A` | 蓝 `#2563EB`   | 正=蓝 / 反=琥珀 `#D97706` | 极细分割线、几乎无阴影、字重对比强、最清晰     |
| **V2 Notion 暖灰**    | `#FAFAF9` | `#1C1917` | 墨绿 `#059669` | 正=靛蓝 / 反=赭红         | 卡片白底 + 柔和阴影 + 12px 圆角，温和          |
| **V3 学术纸感**       | `#FBFBF8` | `#14161A` | 绛红 `#9B1C1C` | 正=藏青 / 反=绛红         | 标题用衬线（思源宋体），正式庄重，适合校级决赛 |

三个方向共用的硬约束：

- 计时数字必须 `font-variant-numeric: tabular-nums`（等宽数字），否则每秒跳动会左右晃。
- 数字字号用 `clamp()` + `vh` 自适应（投影分辨率从 1024×768 到 4K 都要成立）。
- **字体必须本地打包**，不能引 Google Fonts CDN（教室可能没网）。
- 中文字体走系统栈：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC"`；数字用打包的 Latin 字体。
- 底部控制条在鼠标静止 3 秒后淡出（投影上更干净），任意键/移动鼠标唤回。

## 7. 风险与对策

| 风险                                                             | 对策                                                                          |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Linux 渲染是 WebKitGTK（≈Safari），不是 Chromium，CSS 行为有差异 | CSS 按 Safari 兼容写；`browserslist` 目标含 safari；三平台各跑一遍            |
| NVIDIA 显卡 + WebKitGTK DMABUF 黑屏/崩溃                         | `main()` 里设 `WEBKIT_DISABLE_DMABUF_RENDERER=1`（Tauri 官方给的规避）        |
| 老旧多媒体电脑 WebView2 缺失（Windows）                          | 打包时配 `bundle.windows.webviewInstallMode`；Win10 1803+ 系统自带            |
| 老旧电脑性能差                                                   | 方案 B/C 天然优势；避免大范围 backdrop-filter/阴影动画                        |
| 现场误触关闭/切窗口                                              | 全屏 + 关键操作（结束比赛、切换模板）二次确认                                 |
| Vite 8.3.0 与 Tauri 官方模板的版本匹配未知                       | **用 `npm create tauri-app@latest` 让官方模板决定版本**，不手工指定，避免踩坑 |
