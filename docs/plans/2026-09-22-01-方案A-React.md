## 3. 关键实现要点

### 3.1 每帧更新不能重渲染整棵 React 树（A 方案的核心风险）

计时器每秒要更新数字，若把"剩余毫秒"塞进 Zustand 顶层 state，会让整棵树 diff。做法：

```tsx
// store/useTimerStore.ts —— engine 实例放在 store 外，用 subscription 暴露
export const engine = new TimerEngine(); // 单例，React 外

// TimerDisplay.tsx —— 只有这个组件订阅高频 tick
function TimerDisplay() {
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => {
    // 绕过 React，直接写 DOM：0 重渲染
    return engine.onTick(({ remainMs }) => {
      ref.current!.textContent = format(remainMs);
    });
  }, []);
  return <div ref={ref} className="text-[22vh] font-semibold tabular-nums" />;
}
```

低频状态（当前环节索引、running/paused、提示横幅显示与否）才走 Zustand + `useStore`。
**原则：数字走 DOM 直写，状态走 store。**

### 3.2 engine 与 store 的边界

- `engine` 持有 `deadlineAt`、提示点时间戳数组、暂停累积量——**不进 React state**。
- store 只存：`stageIndex`、`status`、`activePrompt`、`topic`、`templateId`。
- 切换环节时：`engine.loadStage(stage)` → `engine.on('finish')` 决定是否自动进入下一环节（默认不自动，等计时员按 Enter，避免现场误跳）。

### 3.3 提示点触发（防漏）

```ts
// 预计算绝对时间戳，tick 只做"跨过检测"
const marks = stage.prompts
  .map(p => ({ at: deadlineAt - p.atRemainingSec * 1000, rule: p, fired: false }))
  .sort((a, b) => a.at - b.at);

tick(now) {
  for (const m of marks) {
    if (!m.fired && now >= m.at) { m.fired = true; emit(m.rule); }   // 休眠醒来会一次性补触发
  }
}
```

### 3.4 时钟校准

```ts
// clock.ts：performance.now 为主，Date.now 为裁判
if (Math.abs(perfDelta - wallDelta) > 1000) → 判定休眠，deadlineAt 按墙钟重算
```

### 3.5 Tauri 侧只做三件事

1. `tauri.conf.json` 配置单窗口、全屏启动、最小尺寸、标题。
2. `capabilities/default.json` 按需开权限（默认几乎全关；若要用 fs 存模板 JSON 才开 `fs` 插件 scope）。
3. 桌面端快捷键（若需要全局热键）用 `@tauri-apps/plugin-global-shortcut`——**但本项目单屏全屏场景，窗口内 `keydown` 足够，优先不用全局热键**，避免与系统冲突。

## 5. 里程碑（A 方案）

| 阶段 | 内容                                                         | 完成判据                                          |
| ---- | ------------------------------------------------------------ | ------------------------------------------------- |
| M0   | `npm create tauri-app@latest`（选 React + TS）→ 空全屏窗口   | `npm run tauri dev` 起窗                          |

## 6. A 方案特有风险

| 风险                                       | 对策                                                                 |
| ------------------------------------------ | -------------------------------------------------------------------- |
| 高频更新引发重渲染卡顿（老电脑上明显）     | 数字 DOM 直写（§3.1）；`TimerDisplay` 单独 memo，其余组件不订阅 tick |
| Zustand store 与 engine 状态双份、易不一致 | engine 为唯一真源，store 只镜像低频状态；所有动作走 engine 方法      |
| React 19 + Vite 8 与 Tauri 模板版本不匹配  | 用官方脚手架生成，不手工指定版本；生成后跑一次 `npm run build` 验证  |
| 依赖变多导致包体膨胀（对比 B/C）           | 不装组件库；`motion` 仅在必要时引入，优先 CSS                        |

---

## 7. 选 A 的理由 / 不选 A 的理由

**选**：你想要最大生态、未来可能扩展（双屏、插件、复杂编辑器）、或希望别人也能接手维护。
**不选**：本项目实际规模不大，React 运行时 + 重渲染治理是额外成本，产物与启动速度略逊于 B/C。
